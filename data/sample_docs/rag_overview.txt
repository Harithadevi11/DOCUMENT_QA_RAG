Retrieval-Augmented Generation, usually abbreviated as RAG, is a technique that combines an information retrieval component with a text generation model. The approach was introduced in 2020 by Patrick Lewis and colleagues at Facebook AI Research. Instead of relying only on knowledge stored in model parameters, a RAG system first retrieves relevant passages from an external document collection and then conditions the generator on those passages.

A typical RAG pipeline has four stages. First, documents are split into small chunks. Second, each chunk is converted into a dense vector by an embedding model. Third, at query time the question is embedded and the most similar chunks are fetched from a vector index. Fourth, the retrieved chunks are placed in the prompt of a language model, which writes the final answer.

The main benefit of RAG is that it reduces hallucination, because answers are grounded in retrieved evidence. Another benefit is that knowledge can be updated by simply re-indexing documents, without retraining the language model. A common drawback is that answer quality depends heavily on retrieval quality: if the correct passage is not retrieved, the generator cannot answer correctly.
